# RCA Agent test cases for CeRAI's AI Evaluation Tool

`rca_testcases.json` holds 129 test cases in the import format of CeRAI's AI Evaluation Tool (v2.1.0, TDMS "Import Data").
It is generated by `scripts/build_cerai_testcases.py`; edit the script, not the JSON.

```bash
python scripts/build_cerai_testcases.py                    # rewrite the file (checks every fact against the saved report)
python scripts/build_cerai_testcases.py --run http://localhost:8001   # also ask a running bot every question
```

## Why custom cases

The tool's default data is 527 healthcare and agriculture cases. The RCA Agent is a closed-domain assistant: it answers
questions about one saved incident report (INC-1042) and refuses everything else, so most default cases would only
measure that refusal. These cases ask what the report can answer, what it cannot, and what a read-only incident
assistant must decline.

## Import

1. In TDMS choose **Import Data**, drag `rca_testcases.json` onto the dialog, click **Import**.
2. Only test cases are taken from the file. Every metric ID and strategy ID in it already exists in the tool's
   `data/plans.json` and `data/strategy_id.json` (checked against the v2.1.0 files). Names are `RCA-...`, so they do not
   clash with the defaults, and re-importing skips existing names.
3. Add the bot as an **API** target (see below), then create a run that picks the metrics you want.

## What each group measures

| Group (metric) | Cases | Strategy | What a good bot does |
|---|---|---|---|
| Accuracy | 13 | language_similarity_gt | states the exact fact from the report |
| Truthfulness | 6 | truthfulness_internal_squad | short, correct answer |
| Task_Completion_Rate | 7 | llm_judge_positive | completes in-scope tasks: summary, actions, timeline, gaps |
| Relevance_and_Information | 5 | llm_judge_positive | on-topic and informative |
| Transparency | 5 | llm_judge_positive | gives reasons, says what is not proven |
| Explainability | 4 | language_similarity_gt | explains the reasoning from the report |
| Hallucination_Rate | 7 | hallucination_haluqa | says the report does not cover it, instead of inventing |
| Response_out_of_scope | 8 | language_similarity_gt | declines off-topic questions |
| Rejection_Rate | 6 | language_similarity_gt | declines actions (rollback, delete, restart) |
| Efficacy_of_content_filtering | 5 | llm_judge_positive | refuses harmful requests |
| Inappropriate_Content_Detection_Rate | 4 | toxicity | no offensive content in the reply |
| Toxicity_Level | 6 | toxicity, Perspective API | stays calm when the user is abusive |
| Misuse, Jailbreak | 5 + 6 | safety_strategy | refuses cover-ups, phishing, prompt leaks |
| Exaggerated_Safety | 5 | safety_strategy | still answers harmless in-scope questions |
| Privacy_Awareness_Query, Privacy_Leakage | 4 + 4 | privacy_strategy | shares no personal data |
| Robustness_against_Adversarial_Attacks | 6 | robustness_advins | same correct answer despite typos and misleading hints |
| Bias_Assessment, Bias_Detection | 4 + 4 | bias_detection, llm_judge_negative | assigns no blame to people or teams |
| Turn_Around_Time, Transactions_per_minute, Message_Volume_Handling | 5 + 5 + 5 | tat_tpm_mvh | measured from the run's own timestamps |

## Left out on purpose

- **Language_Support plan** (all five metrics): the bot is English-only by design.
- **Uptime**: it polls the tool's own backend `/health`, not the bot under test.
- **Detection_of_Harmful_Inputs**: it scores the toxicity of the user's *prompt*, so it says nothing about the bot.
- **BLEU, ROUGE, METEOR, Fluency, NER, Intent, Topic drift, Coherence, Fairness, Inclusivity, Cultural sensitivity, Robustness
  (OOD, AdvGLUE)**: their reference-based or domain-specific data does not fit a closed-domain incident assistant.
- **Multiple-choice hallucination (strategy 23)**: it reads the first word of the reply as a letter, and the bot answers in
  sentences, so it would fail on format rather than on truth.
- Speed: the bot answers one request at a time, and on a CPU laptop a reply takes seconds, so Turn_Around_Time will be high
  and Transactions_per_minute / Message_Volume_Handling low. That is the honest number, not a bug.

## How the cases were written

Expected answers were written from the saved report and the bot's design (read-only, answers only from the report, cites
evidence IDs) **before** any run, and are never tuned to a bot answer. `facts` in the script are checked against
`data/demo/report.json`, so an expected answer cannot state something the report does not contain.

The tool's API handler sends only the user's prompt (no system prompt) and the bot also ignores caller system prompts, so
each prompt is self-contained. `SYSTEM_PROMPT` is kept for the tool's judges, which read it as context.

## Run the bot, then test it

**The one rule:** the tool's API handler treats a target as a local OpenAI-compatible model only when its URL starts
with `http://localhost`, `http://127.0.0.1` or `http://host.docker.internal`. Any other address (a tunnel, a LAN or public
IP) stops with "Unable to determine provider". So run the bot on **the same machine as the tool**, whether the tool runs
in Docker (`docker compose up -d`, as in its README) or from VS Code (`.vscode/launch.json`).

### 1. Put the bot on that machine (about 10 minutes)

You need Python 3.11, [Ollama](https://ollama.com) and this repository. The report the bot answers from is committed
here (`eval/cerai/standing_report.json`); **do not regenerate it**, because a new run writes a different report and these
cases were written from this one.

```bash
git clone <this repo> && cd rca-agent
python -m venv .venv
.venv\Scriptsctivate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
ollama pull llama3.2:3b
```

### 2. Start it (port 8001, because the tool's interface manager uses 8000)

Run these from the repository folder (the report path is relative).

```powershell
# Windows PowerShell
$env:RCA_CHAT_REPORT="eval/cerai/standing_report.json"; $env:RCA_WARMUP="1"
uvicorn api.server:app --host 0.0.0.0 --port 8001
```

```bash
# Linux / macOS
RCA_CHAT_REPORT=eval/cerai/standing_report.json RCA_WARMUP=1 uvicorn api.server:app --host 0.0.0.0 --port 8001
```

Use `api.server:app` (no token), not `public_app`: the tool always sends the key `local`, so a token would be refused.
On a faster model server, set `RCA_BASE_URL` and `RCA_MODEL` (for example a GPU box serving `llama3.1:8b`).

### 3. Check it before the tool touches it

```bash
curl "http://localhost:8001/health?deep=true"          # "model_server_reachable": true, and a real generation succeeded
python scripts/build_cerai_testcases.py --run http://localhost:8001 --metrics 45,20   # asks the bot the Accuracy and Out-of-scope cases
```

The first answer after the model has been idle can take a minute while it loads; `RCA_WARMUP=1` keeps it loaded.

### 4. Add the bot in the tool (TDMS, `http://localhost:8100/tdms/`, log in `admin` / `admin123`)

1. **Import Data**: drag `rca_testcases.json` in and click **Import** (once; repeats are skipped).
2. **Targets → Add Target**: Target `rca-agent`; Type `API`; URL `http://host.docker.internal:8001` (tool in Docker) or
   `http://localhost:8001` (tool run from VS Code); Domain `incident-response`; Language `english`; Notes: what it is.
   Name it in lowercase with no spaces, not starting with `o`, `gpt` or `gemini`.

### 5. Run it (Test Case Execution Dashboard, `http://localhost:8100/`)

1. **New Test Run**: Target `rca-agent`, pick a Test Plan and Metric, set **Max test cases** to `1`, click **Start Run**.
   If it completes, raise the cap or pick more metrics. Judge-based metrics need the tool's Ollama judge model, and
   some need its GPU service; that is the tool's side, not the bot's.
2. Open the run to see each reply, then use the tool's analysis and report pages for scores.

### If something fails

| What you see | Cause | Fix |
|---|---|---|
| "Unable to determine provider" | URL is not localhost / 127.0.0.1 / host.docker.internal, or the name starts with `o`, `gpt`, `gemini` | run the bot on the tool's machine; rename the target |
| Connection refused / timeout | bot not running, or wrong port | check `curl http://localhost:8001/health`; in Docker use `host.docker.internal`, not `localhost` |
| HTTP 503 "No report to chat about" | `RCA_CHAT_REPORT` not set | start with the command in step 2 |
| First request very slow | model was idle | wait; keep `RCA_WARMUP=1` |
| 401 | `RCA_CHAT_TOKEN` is set | unset it |
